## Summary verdicts
- Producer-side replay metrics are internally consistent and bridge-validated.
- `ce_net` is source-clear as expected CE, not realized PnL.
- Expected and realized cost are separated in code, but replay summary means are all-record report values, not executed-only cost views.
- `exec_rate` is internally implemented as `executed_count / total_records`, but the cockpit does not label that denominator and one dashboard spec documents a different denominator.
- `drawdown_proxy` is honestly named as a proxy, but it is not a promotion-grade true max drawdown metric.
- The current replay page still allows false-green interpretation because defaults, denominator labels, and stale/partial qualifiers are not carried strongly enough into the display contract.
